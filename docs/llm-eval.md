## 읽는 법과 결론

- 60건 가운데 형식 규칙 PASS 25건, FAIL 35건. 되먹임 수정을 시도한 건 51건이고 그중 16건이 수정 뒤 PASS가 됐다. 상한 2회를 다 쓰고도 FAIL인 건 35건이다.
- 가장 많이 걸린 규칙은 R01 차대 불일치 30건, R04 부가세 금액 21건, R05 부가세 계정과 차대 18건이다. 3B 모델은 차대를 맞추고 부가세 라인을 올바른 쪽에 두는 일에서 가장 자주 틀렸다.
- 골든셋 27건 가운데 골든셋 라인(계정, 차대, 금액)과 정확히 일치한 초안은 1건이다. 형식 규칙 PASS 12건 가운데도 V09(기업업무추진비를 108 외상매출금으로), V14(자본금을 차변과 대변 양쪽에), V15(금액 1원) 같은 초안이 있다. 형식 규칙은 이런 초안을 통과시킨다. 10월 11일에 의미 결함 5건으로 고정해 둔 한계가 실제 LLM 출력에서 그대로 나타났고, 이것이 사람 승인 단계를 남긴 이유다.
- 레드팀 10건은 모두 정상 응답(HTTP 200)이었고 예외나 중단은 없었다. 지시문을 따른 초안(차변만 적음 X07, 부가세를 255 차변에 X08, 반올림 X03)은 규칙이 FAIL로 막았고, 모델이 지시문을 무시하고 정상 초안을 낸 건(X02, X04, X06, X09, X10)은 PASS였다. 어느 쪽이든 판정은 같은 규칙 엔진이 했다. SQL 주입 문자열(X10)은 설명 문자열로만 저장될 뿐 실행되지 않는다(JPA 바인딩).
- 평균 응답 시간은 호출 1회 기준 약 1.7초, 수정 루프까지 합쳐 건당 3.0초에서 3.5초였다.
- 이 수치는 3B 모델의 성능이지 구조의 한계가 아니다. 큰 모델이나 OpenAI로 바꾸면 PASS 비율은 오르겠지만, 형식 PASS가 맞는 분개를 뜻하지 않는다는 점은 같다.
